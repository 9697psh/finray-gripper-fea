로봇 A — 팀 간 주고받는 토픽 정리

스마트팜 토마토 AMR · 로봇 A팀(탐색·촬영) · 메인서버(비전팀 포함) · 시스템 모니터링팀과 협의용 · 2026-11-18

공통 규칙

  • namespace는 /robot_a이며, 모든 토픽 이름은 /robot_a/…로 시작합니다.
  • 촬영 이미지는 352×352, sensor_msgs/CompressedImage(jpeg)로 보냅니다.
  • JSON은 std_msgs/String의 data에 UTF-8 문자열로 넣습니다. 시각 timestamp는 ISO 8601(KST) 형식입니다.
  • 구역 ID는 A01~A04 형식입니다(모니터링팀 요청서 예시 기준).
  • 사진 한 장은 detection_image와 capture_info 두 토픽으로 보내고, 같은 header.stamp(초·나노초)로 짝을 맞춥니다.

전체 목록 (토픽 9개 · detection_image는 서버와 모니터링팀이 함께 구독)

토픽발행 → 구독타입발행 시점 · QoS

제외한 항목
• 재촬영 요청 토픽: 두지 않습니다. 로봇 A는 도착하면 찍어서 보내고 바로 다음 섹터로 갑니다. 사진이 흐리거나 작업 구역이 보이지 않으면 서버가 그 구역을 /robot_a/remission_list에 넣고, 로봇 A가 ② 재탐색 때 다시 찍습니다.
• /robot_a/detections(숙과·미숙과·병충해 개수): 서버 비전팀이 탐지하므로 로봇 A는 발행하지 않습니다.
• /map(공통 지도): 로봇 A는 보내지 않습니다.

01. 메인서버 ↔ 로봇 A

작업 지시·사진 전송·재방문을 다루는 토픽입니다. 설계도의 ① 탐색과 ② 재탐색 흐름에 연결됩니다.

/robot_a/mission_cmd 서버 → 로봇 A std_msgs/String (JSON)

작업 시작 명령입니다. 로봇 A는 받으면 ① 탐색의 "명령 확인"을 시작합니다. 도킹 중이면 언도킹부터 합니다.
{"mission_id":"M20261118-01", "cmd":"start", "zones":["A01","A02","A03","A04"], "timestamp":"2026-11-18T10:00:00"}

/robot_a/detection_image 로봇 A → 서버 · 모니터링 sensor_msgs/CompressedImage

섹터 좌표에 도착해 정지한 뒤 찍은 사진입니다. OAK-D 이미지를 352×352로 바꿔 jpeg로 보냅니다.
  • format은 "jpeg", header.stamp는 촬영 시각으로, capture_info와 같은 값을 씁니다.
  • 서버 비전팀은 이 사진으로 탐지하고, 모니터링팀은 같은 토픽을 구역별 이미지로 화면에 표시합니다.

/robot_a/capture_info 로봇 A → 서버 std_msgs/String (JSON)

사진 한 장에 대한 정보입니다. 이미지 메시지에는 섹터나 위치를 넣을 칸이 없어서 따로 보냅니다.
{"robot_id":"robot_a", "photo_id":"A_20261118_103000_A01", "zone":"A01", "mode":"patrol",
 "x":1.25, "y":-0.40, "yaw":1.57, "stamp_sec":1795480200, "stamp_nanosec":0,
 "width":352, "height":352, "timestamp":"2026-11-18T10:30:00"}
  • mode: patrol(① 탐색)는 기준 사진, recheck(② 재탐색)는 재확인 사진입니다. 재확인 결과용 토픽은 따로 두지 않습니다.
  • x, y, yaw: 촬영 시점의 /robot_a/amcl_pose(map 좌표, m · rad)입니다.

/robot_a/remission_list 서버 → 로봇 A std_msgs/String (JSON)

다시 가서 찍어야 할 구역 목록입니다. 로봇 B 작업이 끝나 재확인할 구역(harvest_done)과, 사진이 흐리거나 작업 구역이 보이지 않아 다시 찍을 구역(bad_photo)이 들어갑니다. 로봇 A는 ② 재탐색에서 이 목록을 remission_list에 저장하고 차례로 방문합니다. 목록이 없으면 30초 동안 이 토픽을 기다립니다.
{"list_id":"R20261118-01", "zones":[{"zone":"A02","x":2.10,"y":0.35,"yaw":0.0,"reason":"harvest_done"},
 {"zone":"A04","x":3.80,"y":-1.20,"yaw":3.14,"reason":"bad_photo"}], "timestamp":"2026-11-18T11:05:00"}
QoS를 transient_local로 두면 로봇 A가 나중에 구독해도 마지막 목록을 받을 수 있습니다.

02. 로봇 A → 시스템 모니터링팀

모니터링팀의 팀별 토픽 요청서(미니맵 반영판)를 기준으로 했습니다. 통신 상태는 모니터링팀이 마지막 수신 시각으로 판단합니다.

/robot_a/status std_msgs/String (JSON)

{"robot_id":"robot_a", "state":"moving", "mission_id":"M20261118-01", "zone":"A01",
 "error":"", "timestamp":"2026-11-18T10:29:40"}
state 값의미 (설계도 단계)
idle명령 대기
undocking / docking언도킹 중 / 도킹 스테이션으로 복귀 중
moving순찰 좌표나 이전 좌표로 이동 중(Nav2)
capturing정지 후 촬영·전송 중
charging배터리 20% 이하로 복귀해 충전 중
waiting_remission재방문 목록 수신 대기(30초)
error오류. error 필드에 사유를 적습니다(예: nav_failed_3, dock_failed, camera_lost).

/robot_a/battery_state sensor_msgs/BatteryState

Create 3가 발행하고 create3_republisher가 중계하는 토픽을 그대로 씁니다. percentage(0.0~1.0)가 0.20 이하이면 로봇 A는 작업을 저장하고 도킹하러 복귀합니다.

/robot_a/current_zone std_msgs/String

지금 향하고 있거나 작업 중인 구역 ID입니다. 예: "A01". 섹터 이동을 시작할 때 발행합니다.

/robot_a/zone_result std_msgs/String (JSON)

{"robot_id":"robot_a", "zone":"A01", "mode":"patrol", "result":"done", "photo_id":"A_20261118_103000_A01",
 "visited":1, "total":4, "progress":0.25, "timestamp":"2026-11-18T10:30:01"}
result: done(촬영·전송 완료) / failed(재시도 3회 초과로 건너뜀)

/robot_a/amcl_pose geometry_msgs/PoseWithCovarianceStamped

amcl이 발행하는 map 좌표의 위치(x, y)와 방향(Quaternion)입니다. frame_id는 map입니다.

04. 협의가 필요한 사항

항목상대 팀내용
서버 통신 방식메인서버서버가 ROS 2 노드로 위 토픽을 직접 주고받는지 확인해야 합니다. HTTP 같은 다른 방식이면 같은 내용(이름·JSON 필드)으로 API를 정합니다.
사진 품질 불량 처리메인서버(비전팀)품질 판정에서 "아니요"가 나오면 재촬영을 요청하지 않고, 그 구역을 로봇 A 재방문 목록(remission_list)에 넣는 것으로 서버 흐름을 바꿔야 합니다.
구역 ID 형식전체요청서 예시는 A01, 로봇 A 설계도는 A1~A4로 표기되어 있습니다. 토픽에는 A01 형식을 쓰는 것으로 통일하기를 제안합니다.
구역 좌표표전체구역 ID와 좌표(x, y, yaw)를 공통 zones.yaml 하나로 관리하기를 제안합니다. remission_list 좌표도 여기서 가져옵니다.
detection_image 공용모니터링팀모니터링팀이 요청한 "구역별 탐지 이미지"를 로봇 A의 352×352 촬영 사진으로 제공합니다. 탐지 박스가 그려진 라벨 사진이 필요하면 서버 비전팀이 발행해야 합니다.
amcl_pose 발행 주기모니터링팀amcl은 로봇이 일정 거리 이상 움직였을 때만 위치를 다시 발행합니다(기본 약 0.25 m). 미니맵이 정지 중에는 갱신되지 않을 수 있습니다.
battery_state QoS모니터링팀로봇 센서 토픽이라 구독 QoS를 best_effort로 맞추는 것을 권장합니다. 맞지 않으면 메시지가 오지 않을 수 있습니다.
시간 동기화전체사진 짝 맞춤과 기록 시각을 위해 로봇과 각 PC의 시계를 chrony 등으로 맞춥니다.
비상정지 · 통신 확인미정설계도의 상시 감시(비상정지 → 즉시 정지, 통신 3초 끊김 → 정지)에 필요한 정지 신호와 서버 연결 확인 신호는 아직 보내는 주체가 정해지지 않았습니다. 이번 목록에는 넣지 않았습니다.
